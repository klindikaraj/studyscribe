- Code. Lecturers read code aloud and name code elements: modules, classes, functions,
  methods, variables, operators, expressions, statements. Every one of them goes into
  "{key}", even a single method name, written as it would appear in a source file:
  spoken punctuation becomes symbols ("dot" -> ".", "equals" -> "=", "plus equals" -> "+=",
  in the lecture's language too); a name spoken as several words is joined the way the
  programming language being taught does it (camelCase in JavaScript, snake_case in Python),
  unless the lecturer spells it; text values get quotes; calls get parentheses with the
  arguments the lecturer gives. Use only names that are in the transcript or their evident
  code form. Never invent a variable name, an alias, an argument or a value, and never
  rebuild code that is only described or shown on screen: a sentence that describes an idea
  or a formula in words is not code. "explanation" says in one sentence what the code does
  in the lecture.

5. Code. Lecturers read code aloud and name code elements: modules, classes, functions,
   methods, variables, operators, expressions, statements. Every one of them goes into
   "{key}", even a single method name, written as it would appear in a source file:
   - spoken punctuation becomes symbols: "dot" or "punto" -> ".", "equals" or "uguale" -> "=",
     "plus equals" -> "+=";
   - a name spoken as several words is joined the way the programming language being taught
     does it (camelCase in JavaScript, snake_case in Python), unless the lecturer spells it;
   - text values get quotes, calls get parentheses with the arguments the lecturer gives;
   - use only names that are in the transcript, or their evident code form (words joined).
     Never invent a variable name, an alias, an argument or a value. Code shown on screen but
     not said is not in the transcript: do not rebuild it. If a name is not clear, leave the
     item out or {unclear};
   - a sentence that describes an idea or a formula in words is not code: it belongs in
     {concept_keys};
   - only what the lecturer writes or reads as code goes here. The name of an idea, an
     algorithm, a technique or a class the lecturer only talks about goes into
     {concept_keys}, even when a library has something with that name;
   - "explanation" says in one sentence what the code does in the lecture.
